# 备份与恢复

Supabase 免费版**没有每日备份**。整个球群的比分、聊天、语音、账号
全在那一个项目里，而它现在没有任何一份副本 —— 这是这个 App 唯一
一件「数据可能真的没了」的风险，别的问题最多是不好用。

这份手册是照着做一遍的流程，不是建议。**没试过的备份等于没有备份**，
所以下面第三步（真的恢复一次）不能跳。

---

## 备份什么

三样，缺一样都救不回一个完整的 App：

| 东西 | 在哪 | 丢了会怎样 |
|---|---|---|
| 9 张业务表 | Postgres `public` | 比分、排名、聊天、举报、反馈全没 |
| 账号 | Postgres `auth.users` | 表还在，但每一行都指向不存在的人，谁都登录不了 |
| 语音文件 | Storage 的 `voice` 桶 | 聊天记录里的语音气泡全变成点不开的 |

9 张表是：`records`（球员、球局、比赛、球群都在这张）、`club_members`、
`friendships`、`blocks`、`messages`、`reports`、`feedback`、
`app_admins`、`push_subscribers`。

---

## ⚠️ 先说两件不能做错的事

**1. 备份文件里有所有人的私聊。** 它不是代码，永远不要提交进
这个仓库，也别丢进任何会同步到公开地方的文件夹。仓库的
`.gitignore` 已经挡了 `backups/` 和 `*.dump`，但那是最后一道，
不是第一道。

**2. 连接串里有数据库密码，service_role 钥匙更不能外传。**
这两样只在你自己的电脑上用，不要贴进聊天窗口、不要截图、
不要写进任何文件后提交。

## 一、把数据库导出来

### 拿连接串

Supabase 后台 → 左下角 **Project Settings** → **Database** →
**Connection string** → 选 **URI**。

里面 `[YOUR-PASSWORD]` 那一段要换成你的数据库密码（不是登录
Supabase 后台的密码）。忘了就在同一页 **Reset database password**。

> **连不上的话先试这个**：直连地址（`db.xxx.supabase.co`）现在
> 可能只有 IPv6，而很多家宽和手机热点没有 IPv6，表现是
> `Network is unreachable`。同一页往下有 **Session pooler** 的
> 连接串，那个是 IPv4 的，换它再试。

### 导

```bash
mkdir -p ~/rally-backups && cd ~/rally-backups
STAMP=$(date +%Y%m%d)

# 业务数据（public schema，9 张表都在里面）
pg_dump "你的连接串" \
  --schema=public --no-owner --no-privileges \
  -Fc -f rally-public-$STAMP.dump

# 账号。单独一份，因为它在另一个 schema 里
pg_dump "你的连接串" \
  --schema=auth --no-owner --no-privileges \
  -Fc -f rally-auth-$STAMP.dump
```

`-Fc` 是自定义压缩格式，恢复时用 `pg_restore`，比纯 SQL 快也小。

**版本对不上的话**会报 `server version mismatch`。本机的 `pg_dump`
版本不能低于服务器。先看服务器是哪一版：

```sql
select version();
```

然后装对应或更高版本的 postgresql-client。

> **这一步我没法替你验**：这台机器连不上你的 Supabase。
> 上面的命令是标准 `pg_dump` 用法，但 `auth` schema 能不能完整导出
> 要以你实际跑的结果为准 —— 报错就把错误贴给我。

### 检查一下真的导到了东西

```bash
ls -lh rally-*-$STAMP.dump
```

两个文件都该有实际大小。`rally-public` 只有几 KB 的话多半是空的，
回去看命令有没有报错。

## 二、把语音文件导出来

语音不在数据库里，在 Storage 的 `voice` 桶。数据库的 dump **不含**
它们。

Supabase CLI 装好之后（`npm i -g supabase`，然后 `supabase login`）：

```bash
supabase storage cp -r ss://voice ./voice-$STAMP --experimental
```

> `storage` 这组命令还标着 experimental，不同版本参数可能不一样。
> 跑之前先 `supabase storage --help` 看一眼当前版本怎么写。
> 实在不行就在后台 Storage 页面手动下载 —— 现在文件不多。

## 三、恢复演练（**这一步是重点，别跳**）

前两步只是产出了两个文件。**文件能不能用，只有真的恢复一次才知道。**

### 建一个空项目

Supabase 后台 → New project。免费版可以同时有两个项目。
命名建议 `rally-restore-test`，跑完就删掉。

### 恢复

```bash
# 先恢复账号，再恢复业务数据 —— 业务表的外键指向 auth.users，
# 反过来的话会一路报 violates foreign key constraint
pg_restore --no-owner --no-privileges \
  -d "新项目的连接串" rally-auth-$STAMP.dump

pg_restore --no-owner --no-privileges \
  -d "新项目的连接串" rally-public-$STAMP.dump
```

报一些 `role "xxx" does not exist` 之类的警告是正常的（带了
`--no-owner` 还是可能有），**只要最后数据在就行** —— 下一步就是验这个。

### 验：数得对不对

在**新项目**的 SQL Editor 里跑：

```sql
select 'records' as 表, count(*) from public.records
union all select 'club_members', count(*) from public.club_members
union all select 'friendships', count(*) from public.friendships
union all select 'blocks', count(*) from public.blocks
union all select 'messages', count(*) from public.messages
union all select 'reports', count(*) from public.reports
union all select 'feedback', count(*) from public.feedback
union all select 'app_admins', count(*) from public.app_admins
union all select 'push_subscribers', count(*) from public.push_subscribers
union all select 'auth.users', count(*) from auth.users
order by 1;
```

**同一句在原项目里也跑一遍，两边数字要一样。**
这一句就是整个演练的结论 —— 对得上，说明这份备份救得回来。

### 再验一件事：比分还认得出人吗

数字对得上还不够，外键有没有接上也要看：

```sql
select count(*) as 有主人的球员
from public.records r join auth.users u on u.id = (r.data->>'ownerId')::uuid
where r.kind = 'player' and r.deleted = false;
```

这个数该和原项目一致。是 0 的话说明 `auth.users` 没恢复成功，
数据虽然在，但没人登录得进去。

### 收尾

演练完**把测试项目删掉** —— 它里面是一份完整的私聊副本，
留着就是多一个会漏的地方。

---

## 多久做一次

现在这个量级（一个球群、十几个人），**一个月一次**够了。
开放给别的球群之后改成每两周。

真嫌麻烦的话，$25/月 的 Supabase Pro 自带每日备份和 7 天 PITR ——
那笔钱买的就是不用做这件事。但**就算买了 Pro，也要做一次恢复演练**，
理由一样：没试过的备份等于没有备份。
