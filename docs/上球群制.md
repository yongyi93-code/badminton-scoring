# 上球群制：顺序不能乱

球群制把「所有人共用一份数据」改成「每个球群一份」。数据库那边分三段
SQL，客户端是一次发布 —— 中间的顺序错了，代价是历史战绩全部读不到，
或者所有人在几分钟里用不了 App。

跑之前先看一眼：**Supabase 后台 → SQL Editor**。三个文件整段贴进去跑，
一次一个，跑完看输出再跑下一个。

---

## 顺序

```
1. 003-clubs.sql          建结构（成员表、club_id 这一列、按码查群的函数）
2. 004-migrate-to-club.sql 把现有数据归到一个群里
3. 发布新版客户端          （推 main，等 GitHub Actions 跑完）
4. 自己手机上验一遍
5. 005-club-rls.sql       收紧策略：从此只读得到自己群的
```

### 为什么是这个顺序

**003 和 004 必须挨着跑。** 003 加的 `club_id` 这一列，老数据那边是空的。
005 收紧之后，`club_id` 为空的行谁都读不到 —— 中间跳过 004 直接跑 005，
等于把你们现有的战绩全部锁死。004 自己带了一道闸：还有空的行就直接报错
回滚，不会半迁移。

**004 要在发客户端之前。** 新客户端一打开就问「我在哪些球群里」。这时候
数据库里一个群都没有的话，每个人都会看到「先进一个球群」那一屏，然后
各自建一个新群 —— 八个人八个群，谁也看不见谁。

**005 要在发客户端之后。** 005 之后，写进数据库的每一行都必须带
`club_id`，而旧版客户端不带。装着旧版还没更新的人，一记分就报错。
所以先让新版发出去、大家都进来了，再收紧。

---

## 每一步该看到什么

### 003

跑完没有报错就行。想确认的话：

```sql
select column_name from information_schema.columns
where table_name = 'records' and column_name = 'club_id';
```

有一行 = 成了。

### 004

输出里会有一段 notice，记下那个邀请码：

```
建了球群「我的球群」，id=club_xxxxxxxxxxxx，邀请码=K7M4PQ
加了 8 个成员
归了 1243 行数据
```

底下那张自检表要满足：

| 项 | 应该是 |
| --- | --- |
| club_id 还空着的行 | **0** |
| 成员数 | 你们注册过的人数 |
| 球群「…」邀请码 | 记下来 |

「成员数」是从球员记录的 `ownerId` 收集的 —— 只有认领过角色的人才有账号。
代建的访客本来就没账号，不在这个数里，也不影响他们的战绩。

群的名字脚本里写死是「我的球群」。改名不用改 SQL：新版客户端里
**我的 → 球群 → 改名**。

### 4. 验一遍（别跳过）

自己手机上把 App 更新到最新（我的 → 检查更新），然后确认：

- 打开就是首页，**没有**看到「先进一个球群」
- 我的 → 球群，看得到群名字和邀请码
- 记一场分，退到首页再进来还在
- 全体排名里人还是那些人，场次没少

有一条不对就先别跑 005 —— 005 之后再排查会麻烦得多。

### 005

跑之前它会自己数一遍还有没有 `club_id` 为空的行，有就报错回滚，
一条策略都不会改。跑完之后：

- 不在群里的人查这张表，回来的是 0 行（不是报错，就是空的）
- 往别人群里写、或者把自己群的一行改到别人群去，都会被拒

---

## 出了事怎么退

**004 跑坏了**：整段包在事务里，报错就全部回滚，什么都没变。

**005 跑完发现读不到数据**：多半是有行漏了 `club_id`。先把策略去掉，
再补数据，然后重跑 005：

```sql
drop policy if exists "读自己群的" on public.records;
drop policy if exists "写进自己群" on public.records;
drop policy if exists "改自己群的" on public.records;
-- 补完之后重新跑 005-club-rls.sql
```

**有人没进群，界面卡在「先进一个球群」**：把他的账号 id 加进成员表就行，
数据一点都不用动。

```sql
insert into public.club_members (club_id, user_id)
values ('club_xxxxxxxxxxxx', '他的-auth-uid')
on conflict do nothing;
```

他的 auth uid 在 **Authentication → Users** 里，按邮箱找。

---

## 之后新人怎么进来

不用再碰数据库。群里任何人打开 **我的 → 球群**，把邀请码发给他；
他注册完会看到「先进一个球群」，输进去就在了。

邀请码是六位，刻意避开了 0/O、1/I/L —— 这串码是要人在球馆里念给
别人听的。
